# 09 · 确认点与交付物（默认模式）

> 3.4 起统一口径（2026-11-04），4.0 加第零节三个入口：默认模式 = **用户确认故事和剧本 → 自动化流水线（`docs/18`）→ 交付资产提示词 + 投喂包**。文件名保留"两文档交付模式"是为了不打断旧链接，两份交付物现在指下面第三节的 ① 和 ②。
>
> 前面所有岗位的价值，必须落进交付物的每一句里，而不是体现在内部审核记录里。完整模式（`docs/01`）和精简模式（`docs/08`）只在用户明确要求时使用。

---

## 零、三个入口（4.0）

用户怎么来，就从哪里进；三条路在"② 剧本确认"汇合，之后完全一样。

| 用户说 | 入口 | 第一步 | 汇合前要用户点头的 |
|---|---|---|---|
| "给我几个创意" | **A 出创意** | 读 docs/11（口味）+ docs/20 内核闸门；用户给了类型就在类型卡里出，没给就推荐 2–3 张卡；出 3 个拉开的方案，每个带类型卡、时长档位、估价 | ① 故事 → ② 剧本 |
| "我想做个科幻片""有个点子：……" | **B 一个想法** | 先挑类型卡和时长档位（docs/21）；**围绕用户的想法**出 3 个发展方向（不另起炉灶），每个写清选择与代价、结尾那一下 | ① 故事 → ② 剧本 |
| 丢进来一份剧本 / 梗概 / 小说 | **C 现成剧本** | 先写《剧本诊断》（下面），不改用户的字；用户定改哪些后，规范成三件套 | ② 剧本（故事随剧本一起确认） |

**C 入口的《剧本诊断》**（写进 `projects/<项目>/01-剧本诊断.md`，一页）：
1. **一句话**：这个剧本讲的是什么；主角的想要、需要、选择、代价（docs/20 第三节 A–E），缺哪格就写缺。
2. **内核闸门 A–H** 和 docs/11 第八节故事闸门：逐条过 / 不过，不过的给一个最小改法。等救主结构（F）照样一票否决，但先问用户，不擅自改。
3. **规模**：按台词量和场景估时长，落在哪个档位（docs/21）；超过 10 分钟或天然分集的，建议走剧集模式（docs/22）。
4. **类型**：最接近哪张类型卡，影调建议。
5. **能不能拍**：AI 弱点（人物交叉、镜子、文字、一人连做三个动作、多人同时动作、配角太多……，docs/14 4.2）、复杂度红色的场、合规风险。
6. **改编**（小说、网文、长剧本）：按 docs/23 第十节——重构不是翻译；压缩五法（冲突合并、时间跳跃、信息前置、删繁就简、支线 80/15/5）；三删（删人物刻画、删环境渲染、删事件连接）；只能靠内心独白的转成物件、动作或空间，转不了就删。
7. **改动清单**：只列必要的改动，分"必须改（拍不出来或违规）"和"建议改（更好看）"，每条一句理由。

用户确认改动后：用户的台词和情节原样保留，只按清单改；补齐三件套（世界观与美术设定、电影级剧本格式、节奏曲线和回扣表），在 `03-剧本.md` 开头写清"原稿 → 规范稿"改了什么。用户确认后执行 `confirm story` 和 `confirm script`。

## 一、用户只在这几处点头

```
① 故事确认 ──→ ② 剧本确认 ──→ 流水线自动跑 ──→ ③ 批出图预算 ──→ 流水线继续 ──→ 交付 ──→ ④ 批出视频（用户自己出片）
```

- **① 故事确认**：一句话故事 + 分条大纲 + 立项默认设定（类型卡和时长档位从 `docs/21` 选，风格配方随卡给出、可从 `docs/16` 换；画幅、预算估算、配乐字幕、目标视频模型）。
- **② 剧本确认**：世界观与美术设定 + 电影级剧本 + 节奏曲线（`docs/11` 剧本交付三件套）。交之前执笔人按 `templates/剧本验收表.md` 自检，结论 RECOMMEND 才交，三件套开头附"自评最不满意的一处"（docs/23 第十一节）。
- **③ 出图预算**、**④ 出视频花费**：花钱的事只问总量，一个项目问一次。
- 剧本确认之后不再停下来问创作问题，直到交付。

## 二、剧本确认后怎么做（一次通过，不来回）

由**一个执笔者**把剧本拆成 `设定.json` + `分镜.json`（`docs/19`），然后照 `pipeline.py run` 的 NEXT 做到底（`docs/18`）。其他岗位不是"轮流交稿、轮流审核"的环节，而是**拆数据时必须逐项过一遍的视角清单**：

| 视角（原岗位） | 必须落进数据的东西 |
|---|---|
| 总导演 | 每条的价值翻转 `turn`、视听高光 `signature`、压力源 `tension`、全片能量曲线 `energy`、调度与镜头覆盖、轴线 |
| 摄影指导（兼灯光） | 景别 → 焦段、有动机的运镜 `move`、光逻辑、质感（风格配方） |
| 美术指导（兼道具） | 锚点物、光逻辑、时代锁、使用痕迹、画面对冲 `contrast`、空间 `stage`、道具操作机制 |
| 角色造型师 | 描述锁（逐字复用）、剪影识别点、三视图、压力测试（可选） |
| 表演指导 | 每镜一个手上的动作、反应链、情绪先压后放 |
| 台词对白导演 | 台词五招、`delivery`、说话人可见、4.5 字/秒 |
| 声音导演 | 音色锁 `voice`、声源在画里的 `sound` |
| 文戏导演 | 对手戏的 `drama`：双方各想要什么、优势易手那句在第几镜 |
| 武戏 / VFX 导演 | 每个动作镜头的 `hit`（支撑、发力、接触、受力、结果）；每个特效镜头的 `vfx` 七要素 |
| 风格参考总监 | 风格配方、参考片拆出的参数 |
| Image 2.5 资产提示词大师 | 由流水线自动生成资产文档 |
| 合规官 | 无年龄词、无救主结构、真人与版权、尺度 |
| 场记 | 站位跨条接上（或写 `time_jump`）、`splice` 出口、上一条尾帧接进下一条 |

**用户要求清单**（4.0 alpha.7）：用户在对话里说过的每条硬要求，当场写进 `logs/用户要求.md`（一条一行，写日期）。流水线报告会把它列出来，每次停下来、交付前逐条对照。

**冷读**（4.0 alpha.7，可选、不拦）：故事定稿前、花钱出视频前、成片出来后，各派一个**不带上下文**的子代理读一遍材料，只写一页问题清单（`pipeline.py coldread <项目> <故事|投喂前|成片>` 生成任务书，模板 `templates/冷读.md`）。它不改文件、不退回、不开会；执笔的人看完自己决定改不改。每次约多花一个子代理的 token。

**内部检查全部是机检和目检**，写在流水线里：`storyboard.py check` → 资产目检 → 规格自检 → 白模几何检查 → 白模目检 → 编译检查。发现问题就地改数据重跑，不退回、不开会、不出审核报告。

## 三、交付物

| # | 文件 | 内容 | 谁生成 |
|---|---|---|---|
| ① | `交付/01-资产提示词.md` | 出图清单 + 每张图的提示词（标推荐出图模型）、美术要求、出图后检查 | 流水线 assets 阶段 |
| ② | `交付/投喂包/<模型>/第N条/` | 每条一份：提示词、参考图接线（@图片N = 哪张定版图）、白模 `@视频1`、界面参数、检查.txt；按 `production.json` 的 `video_models` 出 Seedance / 海螺 H3 / 万相 | 流水线 compile 阶段 |
| 附 | `交付/规格单/第N条.json` | 镜头规格单，三个模型共用的唯一来源 | 流水线 specs 阶段 |
| 附 | `交付/参考图定版/` | 目检通过的最终图，只放定版图 | 流水线 asset_review 阶段 |
| 附 | `交付/01b-角色压力测试.md` | 开了压力测试才有 | 流水线 stress 阶段 |
| 附 | `交付/03-首帧图提示词.md` | 可选：开场镜头高风险或要接戏的条，一张首帧图的提示词 + 白模构图；用户点头才出图，定稿存 `交付/首帧图/第N条.png` 后自动进投喂包 | 流水线 framesheets 阶段 |
| 附 | `logs/流水线报告.md` | 每条最可能翻车的点、投喂包位置、用户要求、首帧图、冷读 | 流水线 report 阶段 |

**只出 A 白模预演版**（2026-11-02 用户决定）：每条都有白模，投喂包把白模作为 `@视频1`，只提供镜头路线、构图、空间、人物路线与事件先后。

**B 无预演版只是兜底**：本机没有 Blender、或用户明确要求时才写。写法：把白模承担的结构改成文字（机位高度、离人物米数、起止构图、切点清单，圣经第 21–23、28 条），第 24 条触发的条加一张首帧图；B 版不得出现"预演"和"@视频"。

**手写模式**：项目没有 JSON 数据（老项目或 Python 脚本模式），或用户要一份可读的汇总文档时，才手写 `交付/02-Seedance提示词.md`（模板 `templates/交付-Seedance提示词模板.md`），默认只写 A 版，写完跑 `python3 tools/prompt_lint.py 交付/02-Seedance提示词.md --all`。流水线模式不生成这份文档，也不跑 prompt_lint。

## 四、白模预演

每条都出白模（流水线 previs 阶段，`tools/previs/`），由镜头规格自动生成：圆柱 + 球头的代理人物、简化场景、按 `move` 运镜。白模只给结构；脸、服装、表演、质感全部由参考图和提示词决定。特别复杂的地形或奇观运镜用 `cam` 逃生口或 Blender MCP 手工搭（`crew/25-previs-director`）。

## 五、给用户的消息最少化

- 流水线跑的过程中不推送中间稿、不逐个汇报岗位进度；只在要用户点头时停下。
- 交付时一条消息：交付物位置、出图张数、视频条数与总时长、每条最可能翻车的一个点和一行改法、出视频大约要花多少。
