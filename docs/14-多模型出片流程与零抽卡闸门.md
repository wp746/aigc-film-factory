# 14 · 多模型出片流程与零抽卡闸门

> 工厂的核心出片流程（2.0 起）：一个故事写一份**镜头规格单**（单一真相源），白模、预审、三家模型的投喂包和 API 请求，全部从这份规格单生成。出片前必须过**零抽卡闸门**。
> 模型知识见 docs/13；故事闸门见 docs/11 第六节；两个世界的拍法、轴线、过肩见本文第三节。

---

## 一、流程总图

```
故事闸门（docs/11 §6） → 世界观与美术设定 + 电影级剧本 → 用户确认
  → 资产出图（docs/10 + 本文 §五 防 BUG）→ 定稿后把描述锁对齐到图
  → 镜头规格单（本文 §二）+ 白模规格
  → 零抽卡闸门（本文 §四）：规格自检 → 白模几何检查 → 逐帧拼图 → 人工预审
  → 编译投喂包（任选模型）→ 用户在网页上传，或确认费用后用 API 提交
  → 审片 → 抽卡记录 → 规则回填
```

## 二、镜头规格单（`交付/规格单/第N条.json`）

一条戏一个文件，字段：

| 字段 | 含义 |
|---|---|
| `clip` `title` `duration` `ratio` `resolution` | 条号、标题、时长（= 白模时长 = 界面时长）、比例、分辨率 |
| `previs` `previs_spec` `previs_colors` | 白模视频、白模规格 JSON、识别色说明 |
| `assets[]` | 每张参考图：`tag`、`file`、`kind`（character / scene / prop / human_view）、`name`、`duty`（完整的职责句，`@图片N` 占位） |
| `count` | 人数锁："画面中始终只有 N 个有名字的角色……" |
| `context` `two_worlds` `style` | 本条在讲什么；双视角锁；质感 |
| `geo[]` `chars[]` | 空间地图和角色描述锁（完整版才带上；精简版交给参考图） |
| `music` `sfx` `voices[]` `lip` | 声音：配乐、现场声、音色、口型规则 |
| `shots[]` | 每镜：`t0` `t1` `id` `name` `body`。`body` 必须以"画面里：……。"开头，台词写在 `{}` 里 |
| `constraint` `ban` `long_take` | 约束（肯定句）、画外禁名、长镜头理由 |
| `axis` | 可选，`{"a": 人物, "b": 人物}`，几何检查用它查越轴；有意换轴的镜头写 `"new_axis": true` |
| `shots[].allow_small` `shots[].allow_occlude` | 可选。有意拍得很小的人物（如几百米外的人影），以及有意的遮挡物（如人物站在金光柱里），几何检查不再报出 |
| `fail` `risk` `splice` | 翻车判据（只给人看）、最可能翻车和改法、拼接 |

**写法规则**（来自实测）：
1. 每镜开头写"画面里：……。"，列出这一镜画面里有谁。
2. 每句台词的说话人要在"画面里"，或者写明"画外 / 背对镜头 / 过肩"。
3. 齐声只放在士兵背对镜头的群像里。
4. 每镜台词 ≤ 4.5 字/秒。
5. 镜头 ≥ 1.5 秒。
6. 容易变形的道具，每次都写同一个外形（例："一根光滑的圆柱形银色金属针"）。
7. 约束写成肯定句。

## 三、两个世界的拍法（工厂通用）

### 1. 轴线
- 一场对话，在两个主角之间连一条线，整场机位都在线的同一侧；
- 说话人身后不能是他正在说话的对象；
- 有意换轴的镜头，在规格里标 `new_axis`，并且要有新的视线做理由（例："胖针看向远处的小针"）。

### 2. 不拍正反打大头贴
每场对话至少用三种手法：
- 过肩；
- 前景遮挡；
- 纵深移焦；
- 用走位改变景别。

相邻两镜不用同样的景别和角度。

### 2.5 两人同框不拍 90° 侧面；只换景别也要换角度（2026-11-07）

- **中景以上两人全身同框**（对峙、打斗）时，机位和两人连线成 30–60° 斜角，不拍正侧面：正侧面没有纵深，像横版格斗游戏。近景、特写才可以拍正侧面。白模几何检查在"构图"后面列一张"两人同框侧拍"表（只统计，不拦）。
- **相邻两镜只换景别、拍的还是同一个人时**，机位角度至少换约 30°，否则像跳切（分镜大师）。校验器已拦"相邻两镜类型和景别都一样"，这一条在分镜时自己看。
- **转场接点**：跨条、跨场的接点在方向、亮度、色彩三样里至少锁住两样（docs/07）；没有可见接点就硬切或补一个桥接镜，不留给后期猜。

### 3. 竖直物体不放在头后
塔、针、柱子、灯杆，要和人物的头在画面上错开。几何检查会自动报出来。

### 4. 小世界和人间
小世界（拟人化的一方）按真人电影拍：
- 实用光源；
- 手持、推轨；
- 浅景深。

人间按纪实拍：
- 固定机位，或者极慢地推；
- 平光，不调色；
- 没有配乐。

开场先把人间拍满：
1. 全景慢推；
2. 物件特写交代身份和状态；
3. 从高处俯视人物的睡相或生活状态；
4. 声音入画；
5. 镜头再进入小世界。

## 四、零抽卡闸门（出片前必须全过）

| 步骤 | 工具 | 查什么 | 不过怎么办 |
|---|---|---|---|
| 1 规格自检 | `python3 -I tools/compile/check_spec.py 交付/规格单/` | 规格、白模、最后一镜三者时长一致；镜头连续；短镜；"画面里"；台词速度；说话人在画面里；齐声背对镜头；否定写法 | 改规格单，直到没有 FAIL |
| 2 白模几何检查 | `python3 tools/previs/geometry_check.py <白模规格> <规格单>` | 每镜三个时刻：主体入画、主体大小、遮挡、头后竖直物体、机位穿墙、越轴。读"画面里"时有几条规则：镜子里和画像里的人不算主体；只露手、脚、鼓面的特写不查头；写了虚化、背影、背对镜头的人算前景；越轴只看同时出现两个轴线人物的镜头 | 改白模机位或人物站位，重渲白模 |
| 3 逐帧拼图 | ffmpeg 每 0.5 秒一帧拼图 | 物件镜头、人间镜头这些几何检查管不到的构图 | 人工看图，改白模 |
| 4 锁和图对齐 | 人工加视觉 | 描述锁写的内容和定稿图一致（数量、位置、颜色、形状） | 改描述锁，不重出图 |
| 5 预审报告 | `logs/第N条预审.md` | 前四步的结论、剩余风险，以及事先约定"局部可用、不重抽"的标准 | — |
| 6 模型硬限制 | 编译时自动写进 `检查.txt` | 时长范围、参考图数量、字数上限 | 换模型或拆条 |

### 4.1 实拍教训（《天劫外包》第 1 条，2026-11-03，Seedance 2.5 一次出片，审片 21.5/24）

闸门管住了"硬"的部分：切点和白模逐帧一致（5 / 8 / 13 / 18 / 21.5 / 24 秒），轴线和过肩没乱，5 句台词一字不差、说话人对，三个角色的脸和服装对得上，卷轴上没有字。丢分都在下面四类"软"细节，以后写规格单时照做：

| 丢分 | 原因 | 规则 |
|---|---|---|
| 长廊里没有正式工，只有空走廊，"一排人敲鼓像打印机"的笑点没了 | 场景参考图是空场；提示词只说"正式工们"，没给人 | **画面里写到路人，就上传本世界的群像（docs/17），按群演编号点名、写清几个人、在哪、做什么动作** |
| 长廊几乎没声音（空调、敲鼓都没有） | 模型只给"看得见声源"的环境声配音；画里没人敲鼓，就没有鼓声 | 声音仍由声音导演写进提示词（这条其实写了三处），但要绑定画里看得见的声源和动作（"两侧正式工一个接一个敲鼓，鼓声随鼓槌起落"）；出片后量音量，某段明显没声才用后期补，后期只兜底 |
| 光环"闪两下再弹一下"不明显；"拇指按在布鞋上"变成另一只手的食指 | 对白镜头里塞了小动作，模型优先保台词；插入镜头没说是谁的手 | 对白镜头最多一个小动作，写在第几秒、用什么手指；手部特写写清"谁的手、袖口什么样" |
| 小雷"站在工位里"变成坐在椅子上 | 参考图里工位有椅子和桌子，模型按常理让他坐下 | 姿势要和参考图里的环境一致；要站着就写"没有椅子、站着" |

### 4.2 外部实测的模型错误表（Eian，2026-11-05，Seedance 2.5 / 2.0 mini + 首尾帧工作流；只收我们用得上的）

| 模型容易犯的错 | 写法 |
|---|---|
| 一群人同时做同一个动作 | 写清谁先谁后（"第一个……过一两秒……最后……"）；参考图里也不要摆同一个姿势（校验器会提醒） |
| 本该风做的事，人自己动手做了 | 写清原因，再写"两只手从头到尾没有碰它" |
| 云、月亮、植物长出眼睛和嘴 | 不写"卡通云"，写"蓬松的灰白积云，只有棉絮一样的纹理和阴影"，动作只写它怎么移动 |
| 人往反方向走 | 方向按画面写："朝画面左边走" |
| 一句话两种意思（"窗户后面的老人"→车里冒出人） | 写具体位置："左上角石头房子的窗口里"，再加"驾驶座一直空着" |
| 东西数量变了 | 直接写数量："只有一封黄信封" |
| 写"不要怎么样"没用 | 改成肯定句："画面里一直只有这几个人"（工厂规则，已有） |
| 模型自己联想道具的用法（壶一出现就出水） | 这个道具不进有动作的镜头 |
| 东西凭空出现 / 瞬移 | 只用参考图里已有的东西；写清它怎么动过去 |
| 雨、帽子、纹身拍着拍着没了 | 写进描述锁并在参考图里画出来；高风险镜头考虑首帧图 |
| 闪电画得太写实 | 写"云里闪一下白光"，后期剪掉开头 |
| 一镜动作太多就乱 | 每镜一两个主要动作（校验器会提醒） |
| 动作时间和写的不一样 | 写的时间只算大概，多留一点余量，后期剪辑和变速对齐 |
| 推镜没有写的那么明显 | 后期用代码再推一点 |
| 人的嘴自己在动 | 写"人物不说话"，还动就后期修 |
| 2.5 写了"无音乐"仍混进音乐 | 片段自带的音轨不用，后期整轨替换 |
| 2.5 最后几帧突然跳到尾帧的样子 | 后期停在最后一张正常的帧上 |
| 2.5 第一帧特别锐 | 剪掉第一帧 |
| 铁管、绳子、链条、飘带这类柔性细长道具穿模、断开、穿过身体（《列阵》不可生成镜清单） | 不让它进有动作的镜头；必须有时只拍静止的状态，动作挪到后期或换成硬的短道具 |
| 一镜里塞了顿帧、0.3 秒特写、五人围攻 | 这些本来就是剪辑做的：生成时拍完整的动作，顿帧和极短特写在后期剪（crew/15 后期补物理） |
| 多镜之间光线乱跳（待实测） | 摄影词典的经验：写一个具体钟点（"下午三点四十"）比写"午后"更能稳住多镜的光；声明"三个硬切、共 X 秒"能控制镜头数。工厂还没实测，先不进编译器 |
| 白模里的彩色小人原样出现在成片里（万相 3.0，用户朋友实拍，2026-11-07） | 提示词逐个写"紫色带关节的纯色小人 → 图5「某某」"，白模长什么样照实写；白模里的每个人都要有参考图，超上限就拆条（docs/13 八·六，4.0 alpha.10 已进编译器和校验器） |
| 坐在轿里、躲在柜里的人被画到外面（实拍《好日子》第 6 条） | cast 里写 `hidden`：白模不渲，提示词写"全程看不见"（docs/19） |
| 大全景里人物只有几个像素，模型认错谁是谁 | 在这一镜的动作里写清"花轿左边是村长、右边是秀英"（实测有效） |
| 成片里凭空多出巨大暗影、极小的人 | 风格配方里出风格样图用的画面内容进了视频提示词；视频只用配方的 `video_zh` / `video_en`（docs/16） |
| 小数秒的条被截短半秒 | 三家时长都是整秒：编译器向上补齐，白模补静帧，粗剪剪回去 |
| 2.0 mini 越往后越暗越冷 | 后期自动修：同一场连续的下一条对齐上一条的尾帧；单镜头的条按时间补回（`tools/post.py`） |

**修片阶梯**（和 docs/04 停止规则一致；剪头尾坏帧、补尾帧、调色对齐、转场、换音轨用 `tools/post.py`，docs/21 第五节）：能剪掉就剪 → 能用代码修就修 → 修不了才改提示词或参考图、只重拍这一镜。原样再拍一次大概率还是错的。旧片段一律保留，最后一起挑。

**提醒**：这道闸门把已知的翻车原因都挡在出片前，但生成模型有随机性，不保证一次通过。每条出片后都要记一次通过率，翻车的原因写回这张表。

### 4.3 提交前逐镜预审（2026-11-08 至 09，《好日子》实测总结，三家都适用）

用户的要求：点生成之前就要知道这个镜头对不对；生成一次很贵，不靠抽卡。每条提交前写 `logs/第N条预审.md` 给用户看，用户点头才提交。逐镜查下面每一项，出片后逐镜审片也按同样的项（docs/04）：

1. **拆条按剧情，不凑满时长**：一条只装一个情绪落点；镜头越多，一次全对的概率越低（每镜 85% 的把握，7 镜全对只有约 32%）。
2. **开头画面里有什么、道具在谁手里**，谁把它带进来、带出去；没写，模型会自己放一个，让人自己递给自己。
3. **动作人能不能做出来**：一只手做不到的事（用攥着别人手腕的这只手，去掏这只手自己袖口里的东西），模型会多变出一只胳膊。
4. **先定身体，再推手**：有手的画面，先写每个人的身体在画框哪一边、朝哪，再写左右手的位置，核对每只手的胳膊能接到对的肩膀上；拿东西的手势要合用途（梳子拿梳背，不捏梳齿）。
5. **场面布局和人物状态**：两人以上同场，写谁坐谁站、面朝哪、离门窗家具多远、谁在门里谁在门外；每人的姿势、发型、手里的东西整条不变，每一镜都重说一遍。否则模型每镜各摆一套。
6. **这一镜要看清谁的脸**，机位放在哪一边才看得到；情绪落点的那张脸不能背对镜头。
7. **句子不打架**：音色锁和这一句的语气（"像在台上主持"对"耳语"）、表演和"不入画"、写的左右和布局推出来的左右。打架时模型只挑一句听。
8. **音量单独写一句**：小声、耳语、喊，写成看得见的身体（低头、嘴唇只微动、几乎是气声），不只放在括号里。
9. **克制的表情写具体**："不露牙的小笑一点没变、不笑出声"；写"笑得一模一样"会被演成开怀大笑。
10. **动作做完就停住**：镜头比动作长时，写"做完就停住，保持到切镜"，否则模型自己补动作。
11. **手上的戏放在近景里会被加一刀特写**：要么单独写成特写镜头，要么写"一个镜头拍完，脸和手同时在画里"。
12. **带字的东西不入画**：信、招牌一入画，字就被画成清楚的假字；写"挡住、模糊"不管用。
13. **动作写清对谁做**："给阿禾梳头"，不写"接着梳头"。
14. **只写这一段真发生的事**：约束里写的道具操作、别的条的动作，都会被演出来。

**机检已接上的部分**（4.0 alpha.12，部分学自 scenario-labs 的 blockout skill）：
- `storyboard.py check`：连着两个物件特写报警（观众一直看不到人，张力掉；确实要连着拍写 `insert_pair: true`）；喂白模出 Seedance 的条超过 15 秒报警（外部实测 10–15 秒的片段机位和布局保得住，20–30 秒会漂）。
- 白模几何检查加"身份"一行：两个人的身子叠在一起、头钻进墙或家具、半人高的道具立在人身边（会被读成多出来的人），都报 WARN；另加"机位高度"统计，列出不是人眼高度的镜头，分镜里要说得出理由。
- `pipeline.py qc`：每镜每秒 4 帧的逐镜图（`logs/审片逐镜_第N条/`）；有白模的条加白模和成片左右并排图（`logs/审片并排_第N条.jpg`），一眼看出机位、切点、多出来的人和白模残留；报告先列"逐镜目检"表（写的 / 实际 / 判断）再打 24 分；没装 faster-whisper 时用 openai-whisper 听写台词。

## 五、资产出图防 BUG

**出图前**，提示词里必须写清：
- 每样东西的数量："exactly two grains of rice"；
- 图里不能有任何文字："no letters, words, numbers or labels anywhere"；
- 机位："camera almost on the floor, eye level"；
- 不能变成什么形态："it must not read as a dish or a bowl"；
- 不该出现的东西不写进描述。例：拖鞋营房的提示词里写了"远处的蚊香"，模型就把蚊香画进了拖鞋里。

**出图后**按下面的清单检查：
- 有没有文字；
- 数量对不对；
- 有没有多出来的物体；
- 尺寸够不够（Image 2.5 常回 2000×1125）；
- 正面全身像的脸有没有模糊掉；
- 有没有俯视成碗之类的形态错误。

**定稿后**：把描述锁改成图里真实的样子（本文 §四 第 4 步），并重新导出规格单。

**首帧图**（4.0 alpha.7，可选）：一条视频只有**第一帧**能用一张图锁住，所以只给开场镜头高风险的条加：
- 流水线自动挑：开场镜头里有雨、湿、帽子、纹身、眼镜、首饰、文字、招牌、屏幕、镜子、面具、印章、徽章；或这一条要接上一条的戏。
- 写进 `交付/03-首帧图提示词.md`：构图取白模第一帧（`交付/首帧图/第N条_白模构图.jpg`，参考图1），人和物取定版资产图；只描述动作开始之前的那一瞬间；接戏的条再加上一条的尾帧。
- 出图照常先报张数和花费（Image 2.5 带参考图约 $0.045 / 张），用户点头再出；目检通过存成 `交付/首帧图/第N条.png`，再 `run`，它就作为最后一张参考图进这一条第一段的投喂包（"本条的第一帧"），原来的图号不变。
- 不想要：`production.json` 写 `"first_frames": false`。

## 六、编译与提交

- **编译**：`python3 -I tools/compile/compile_video.py 交付/规格单/第N条.json --model seedance|hailuo|wan|all [--style lean|full]`
  - 万相默认不喂白模（只传图，条 ≤ 30 秒）；`production.json` 写 `"wan_previs": true` 才喂（docs/13 第七节）。
  - 输出到 `交付/投喂包/<模型>/第N条[_k]/`。目录里有按编号排好的参考图、白模（海螺、万相会按切点截成 ≤ 15 秒的子段）、提示词、界面参数、API 请求、检查结果。
  - `lean`（默认）：只带素材职责句、人数、轴线、时间轴、声音和约束。
  - `full`：再带上空间地图和角色描述锁。
- **网页出片**：照"界面参数.txt"设置，按编号上传参考图和白模，把"提示词.txt"整段粘贴进去。
- **API 出片**：`python3 -I tools/video_submit.py <投喂包> [--confirm] [--url-map urls.json]`。
  - 不加 `--confirm` 只打印要提交的内容和费用。
  - 参考视频在方舟和百炼只能用公网 URL。
  - 已对照官方文档实现：Seedance（火山方舟）、海螺 H3（MiniMax）、万相 3.0（百炼）的创建任务请求。**三家都还没用真实密钥实测过**；海螺的查询任务路径是推断出来的，第一次用时先在控制台核对。

## 七、已知局限（如实列出）
1. 几何检查只认得白模里的人物代理（圆柱加球头）；物件特写、人间镜头的构图，仍然靠逐帧拼图人工看。
2. 精简版提示词仍然在 1500–2800 字之间，超过 Seedance 官方建议的中文 500 字。哪种写法更稳，要靠同一条戏分别用精简版和完整版出片来对比，结论写回 docs/13。
3. 单条出片的随机性：同一份提示词不同抽数之间仍有差异；闸门能把首抽稳定在约 85–92 分（24 分制 20.5–22），95 分以上需要后期兜底（缺声时补环境声、调色）和对白镜头里不塞多余动作共同保证。
