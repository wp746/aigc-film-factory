# 18 · 自动化流水线（剧本确认之后全自动）

> 2026-11-03 建立。目标：用户确认故事和剧本之后，资产 → 出图 → 白模 → 闸门 → 投喂包由一条命令按固定顺序跑完；**任何智能体**（Claude Code、Codex、Cursor、WorkBuddy……）在本仓库跑，产物都一样。
> 一条命令：`python3 tools/pipeline.py run projects/<项目>`。进度：`python3 tools/pipeline.py status projects/<项目>`，**最后一行 NEXT 就是下一步，智能体只照 NEXT 做，不自己发挥顺序。**

---

## 一、用户要确认什么（只有这几件事）

| 什么时候 | 用户确认什么 | 记录命令（用户在对话里明确说了才执行） |
|---|---|---|
| 故事 | 一句话故事 + 分条大纲 + 立项设定（含画风：从 docs/16 风格库挑） | `pipeline.py confirm <项目> story` |
| 剧本 | 设定 + 剧本 + 节奏曲线 | `pipeline.py confirm <项目> script` |
| 影调（批量出图前） | 2–3 套候选影调的试拍对比图（每套 3–4 个关键时刻，约 10 张、0.4 美元），挑一套写成 `film_look` | `tools/look_test.py`（docs/16 第六节） |
| 出图花费 | 要出几张、走哪个接口、大约多少钱（每个项目一次，可以一次批全量） | `pipeline.py approve <项目> images <张数>` |
| 出视频花费 | 接入出视频接口后同理（尚未接入） | — |

其余全部自动。花钱的事永远要用户点头（CLAUDE.md 第 7 条），但只问一次总量，不逐张问。

**用户在流程中途改主意**：改对应的脚本数据后重跑 `run`，流水线只重做受影响的阶段（按文件指纹判断）。

## 二、阶段（顺序固定，不可跳）

| 阶段 | 做什么 | 停下来的条件 → NEXT |
|---|---|---|
| confirm | 检查故事、剧本已确认，两个项目脚本存在 | 未确认 → 找用户确认 |
| assets | 校验 `设定.json` 并生成 `交付/01-资产提示词.md`；检查每张图有提示词、有 STYLE 段、没有颗粒 / 毛孔词、依赖顺序对 | 不合格 → 改脚本 |
| images | 缺的图按清单顺序出（`tools/image_gen.py`，默认 APIMart Image 2.5 2K，带参考图自动上传） | 超出已批预算 → 找用户批 |
| asset_review | 新图（或被重出的图）标"待目检"，生成拼图 `logs/待目检_资产.jpg`；全部 pass 的图拷进 `交付/参考图定版/` | 有待目检 → 智能体目检；有 fix → 改提示词、redo |
| sound | 声音资产（crew/09）：每个场景一段环境底，可选配乐（本地 Stable Audio），只在后期铺底；对白音色默认交给视频模型自己出，`voice_refs` 为 user / tts 时才有音色参考并接进投喂包（docs/13 第八·三节）；写 `交付/02-声音资产.md` 和每项的工具参数；缺的由智能体用本机工具生成（免费，不占预算），流水线检查时长、响度、削波。声音没人听过时报告里写明。`"sound_assets": false` 可关 | 缺文件 → 按清单生成；不合格 → 重生成或裁剪 |
| stress（可选） | `production.json` 写 `"stress_test": true` 时：每个主角在本片光下出 3 张压力测试（3/4 中近景、暗处全身、双人同框），目检同一个人、像真人、剪影认得出才往下走（crew/07） | 超预算 / 待目检 / fix 就停 |
| specs | 校验 `分镜.json` 并导出白模规格和镜头规格单（docs/19） | ERROR → 按说明改 JSON |
| previs | 白模规格变了的条重渲白模（Blender） | 渲染失败 → 看日志 |
| check_spec | 规格自检（时长和白模一致、画面里、台词速度、说话人入画、否定写法） | FAIL → 改 JSON |
| geometry | 白模几何检查（入画、大小、遮挡、头后、穿墙、越轴、过肩前景出画），WARN 也拦 | 改站位 / 景别 / 机位，或标明有意 |
| framesheets | 每条每 0.5 秒一帧拼图 `logs/白模拼图_第N条.jpg`；白模变了的条标"待目检" | — |
| previs_review | 每条白模都要目检通过 | 有待目检 → 智能体目检 |
| compile | 按 `production.json` 的 `video_models` 编译投喂包；检查不缺图、无新 FAIL | 缺图 / FAIL → 按提示处理 |
| publish | 剧集模式才做：每集 `交付/发布包.md`（封面提示词、片尾与下集预告、文案、合规）；单片跳过 | 季.json 缺发布文案 → 补上（docs/22） |
| report | 写 `logs/流水线报告.md` | — |

状态都在 `projects/<项目>/production.json`：`confirm`、`budget`、`video_models`、`pipeline`（每阶段完成时间和指纹）、`reviews`（每张图、每条白模的目检结论）、`known_fails`（确认不提交的段落）。

## 三、智能体要写的两份数据（这是唯一需要创作的地方）

剧本确认后，把剧本拆成 `projects/<项目>/设定.json` 和 `分镜.json`，**格式和拆法见 docs/19**，照 `examples/样例-便利店/` 写。写完跑 `python3 tools/storyboard.py check projects/<项目>` 直到通过，再 `pipeline.py run`。

- 机位坐标不用算：按镜头类型（全景、单人、过肩、插入、跟拍、主观）和景别自动算，过肩自动选轴线同一侧。
- "画面里"那句、说话人写法、群演点名、每条带哪些参考图，都由工具按固定规则生成。
- 规则写在校验器里（docs/19 第四节），不靠记忆。

**高级写法**：特别复杂的调度（多地点穿插、大运镜奇观）可以改用 Python 数据脚本（`pipeline.py init` 拷 `templates/project/` 两个脚本，公共库 `tools/projectkit.py`）。项目里没有 `设定.json` 时，流水线自动走脚本模式。

## 四、目检怎么做（每个智能体都按同一张清单）

目检是唯一要"看"的步骤，必须由有视觉能力的智能体逐张打开原图做，不能跳过、不能凭文件名判断。

**资产图**：对照资产文档里该图的「出图后检查」逐条看，再加四条通用检查：
1. 图里没有任何文字、编号、水印、乱码；
2. 人数和描述一致，场景图里没有多出来的人，没有黑边；
3. 风格和所属配方一致：近真人写实、没有卡通感、没有颗粒噪点；
4. 三视图的正面全身像脸是模糊椭圆，右侧大头像清楚；群像高矮拉开、没有撞脸。

判决只有三种：
- **pass**：合格；
- **pass + 描述跟图**：小出入，先改脚本里的描述锁，再 pass；
- **fix**：不合格，写明原因，改提示词后 `redo`。

**白模拼图**：对照每镜的「画面里」看：
1. 主体都在画里；
2. 过肩的前景人物入画；
3. 没有东西挡住说话人；
4. 特写拍对了东西；
5. 镜头没有穿进墙里。

## 五、为什么换智能体也一样

0. 第一次用先跑 `python3 tools/pipeline.py selftest all`（单片和剧集两套样例）；新建单片项目用 `pipeline.py new projects/<项目> <片名>`：不花钱，从样例跑到投喂包并和标准产物逐字比对，通过才说明这台机器和这个智能体能稳定生产。

1. 顺序、检查、文件格式都在代码里（`pipeline.py`、`projectkit.py`、`check_spec.py`、`geometry_check.py`、`compile_video.py`），不靠智能体记文档。
2. 每次停下都写明 NEXT，智能体照做即可。
3. 文件指纹决定重做什么，不会漏做或多做。
4. 唯一的创作（两份数据脚本）和唯一的主观判断（目检）都有固定格式和清单，结论记在 `production.json`，换人接手能看到前一个的判断。
5. 密钥只在 `.env`，模型和接口在 `config/image_providers.json`，换机器只需填 `.env`。

## 六、还没自动化的（如实列出）

- **出视频（4.0 alpha.8，`tools/produce.py`，APIMart 的 seedance-2.5）**：
  1. `produce.py <项目> plan`：每条输出秒数 + 白模秒数 → token → 预计花费，写 `logs/出片计划.md`，报给用户；
  2. 用户确认花费后 `pipeline.py approve <项目> video <元>`；
  3. `produce.py <项目> next`：按条号出下一条。参考图和白模先上传换公网 URL（免费，有缓存），提交、轮询、下载到 `出片/第N条.mp4`；接口返回的最后一帧存成 `交付/衔接/第N条_尾帧.png`，下一条要接戏时自动重跑流水线把尾帧编进去；跑 `pipeline.py qc`，记出片记录和花费；
  4. 智能体逐帧目检这一条（docs/04 24 分制，对照白模和参考图），过了再 `next`；不过就按修片阶梯处理（docs/14 4.2），**不原样重抽**；
  5. 全部出完 `produce.py <项目> post` 粗剪（`tools/post.py --ambience`）。
  - 提示词里不能有"编辑、延长、续写、删除、替换"这类词，否则接口会当成编辑 / 延长任务；`plan` 和 `next` 都会查。
  - `tools/video_submit.py` 保留给火山方舟、MiniMax、百炼的官方接口。
- **跨条衔接**：同一场连续的戏，上一条出片后 `python3 tools/pipeline.py splice <项目> 第N条 <视频>` 截尾帧，再 `run`，下一条投喂包自动接上这张尾帧（docs/07）。出片按条号顺序。
- **审片**：`python3 tools/pipeline.py qc <项目> 第N条 <视频>` 自动量时长、切点、每镜音量、台词听写（装了 faster-whisper 时），生成 `logs/审片_第N条.md` 和拼图；24 分制的打分仍由智能体看片填写（docs/04）。后期补声、剪辑仍是手动。
- **冷读**：`pipeline.py coldread <项目> <故事|投喂前|成片>` 只生成任务书，要智能体自己派一个不带上下文的子代理去读（docs/09 第二节）。
- **白模机位**：按镜头类型自动算，常见镜头够用（9:16 的全景自动装人，docs/22 第七节）；奇观大运镜用 `cam` 逃生口或脚本模式手写，靠几何检查和白模目检兜底。
